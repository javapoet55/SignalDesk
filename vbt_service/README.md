# Finviz strategy backtests

Open **Strategies**, select a completed daily close run, then use **VectorBT PRO backtest**. In the VectorBT PRO workspace, choose a saved run and one or more symbols. **Backtest history** lists recent jobs.

Saved-signal mode uses actual buy signals recorded before the next available opening price. It groups matching strategy versions. For older runs lacking a version hash it groups by strategy name. Python replay evaluates the current daily `finviz_signals` strategy for the selected tickers together, with price history capped at each evaluation date. A date range re-evaluates the strategy on each NYSE session for that fixed list. Selecting tickers from a later run introduces hindsight in the ticker selection. Multi-timeframe, V5 and whole-script strategies can use their saved daily signals.

The engine starts each simulation with $100,000, fills a new portal buy at the closing price of its daily signal bar, and first evaluates exits on the following session. A profit target fills on its first touch, at the open if the market gaps above it, or at the seventh following session’s close if the target is missed. With no target, the exit is at the open the specified number of trading sessions after entry. It models long positions, one at a time per symbol, with the supplied percentage-based fee charged on both fills. Historical baskets split $100,000 equally among selected symbols and keep each allocation independent. Portfolio statistics use their combined equity, and the benchmark holds the same equally weighted starting basket. Fee input to the worker is in basis points. Each fold starts flat. Daily equity marks any remaining positions at the final close, and trade statistics count closed positions. Training selects the holding period with the highest return among periods that produced trades. Walk-forward folds train on expanding windows and validate on subsequent bars. Equity and drawdown use daily closes.

## Services

- Finviz Agent requires `VBT_SERVICE_URL` and `VBT_SERVICE_TOKEN`. Both are server-side variables. The standalone service contains no uploaded strategy code.
- Build the `api` stage of this directory's Dockerfile from the repository root. Give it the service token, private `DATABASE_URL`, private `REDIS_URL` and `PORT`. Run it on Railway's private network.
- Build the `worker` stage in a private build context containing this directory and an authorized VectorBT PRO distribution at `licensed/vectorbtpro.tar.gz`. The verified package is 2026.10.5 at revision `673fd69ae72e74dda7636f8abdab19d72bb74b01`. Keep the licensed archive outside the Git checkout. The worker requires only the private database and Redis connection variables.
- PostgreSQL stores job inputs, historical price snapshots and results. Redis wakes workers after submission. Row locks prevent duplicate processing by concurrent workers. An interrupted job becomes available again when PostgreSQL releases the transaction.

**Backtest all buy signals without a date range** evaluates every distinct buy ticker in a selected run as a separate trade for each requested holding period. The entry is the first NYSE session open after both the signal date and run completion. The result uses saved Finviz opening prices and shows pending sessions and missing prices per symbol. Submit the original run again when newer prices are available to create a refreshed snapshot.
